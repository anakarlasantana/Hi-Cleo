## ⚪ FUTURO — FLUXOS AVANÇADOS

### 32. Conversation Flows Engine (State Machine)

**Prioridade:** Média (melhoria de arquitetura, não bloqueia funcionalidade)
**Quando:** Quando precisar adicionar 3+ fluxos conversacionais novos

**Contexto:** Hoje o onboarding usa switch/case hardcoded nos steps. Com a adição de múltiplos fluxos (owner onboarding, collaborator onboarding, upgrade via Cleo, cancelamento via Cleo), o código fica espalhado e difícil de manter.

**Proposta:** Abstrair em um sistema plugável de máquina de estados:

```typescript
const FLOWS: Record<FlowType, FlowDefinition> = {
  owner_onboarding: {
    steps: [
      { id: 'confirm_name', handler: handleConfirmName, next: 'configure_welcome' },
      { id: 'configure_welcome', handler: handleWelcome, next: 'configure_hours' },
      { id: 'configure_hours', handler: handleHours, next: 'completed' },
    ]
  },
  collaborator_onboarding: {
    steps: [
      { id: 'confirm_name', handler: handleConfirmName, next: 'configure_hours' },
      { id: 'configure_hours', handler: handleHours, next: 'completed' },
    ]
  },
}
```

**Benefícios:**
- Adicionar fluxo = criar objeto declarativo (sem mexer no processor)
- Cada step é testável isoladamente
- Suporta branching condicional
- Base para features futuras (agendamento, upgrade, FAQ personalizado)

**Implementação:**
- Nova tabela `conversation_flows` (substitui `onboarding_states`)
- Módulo `flows/` com flow engine genérico
- Migrar onboarding existente para flow definitions
- Não precisa de biblioteca externa (XState é overkill)

**Estimativa:** 2-3 dias

## Fluxo completo do serviço em produção

```
CLIENTE NOVO (Owner):
  hicleo.com.br → Escolhe plano → Paga (PIX/cartão)
    → Webhook MP confirma → Cria user (email + plan + subscription)
    → Gera código ATIVAR-XXXX vinculado ao user_id
    → Redireciona pra /ativacao?code=ATIVAR-XXXX
    → Usuário abre WhatsApp da Cleo, manda código
    → Cleo busca user existente, complementa com phone/name
    → Onboarding conversacional (nome, boas-vindas, horário)
    → /conectar mostra "0 de N conexões" + QR Code
    → Escaneia QR Code → Cleo começa a trabalhar

COLABORADORES (planos Equipe/Empresa):
  Owner conectado diz pra Cleo: "convida 11999887766"
    → Cleo verifica slots disponíveis
    → Gera invite token (72h validade)
    → Envia link pro colaborador via WhatsApp
  Colaborador recebe link → /conectar/convite?token=XXXX
    → Aceita termos LGPD
    → Onboarding leve (nome + horário)
    → Escaneia QR Code → conectado com business profile próprio

DESCONEXÃO/SUBSTITUIÇÃO:
  Owner diz: "desconecta 11999887766"
    → Cleo desconecta a sessão → libera o slot
    → Owner pode convidar outro colaborador

OPERAÇÃO DIÁRIA:
  Aluno/cliente manda mensagem → Evolution API → Webhook → Fila
    → Regras automáticas (boas-vindas, fora de horário)
    → Lead criado automaticamente
    → Follow-up se não responder em 48h

  Professor/dono conversa com Cleo:
    → "quem tá sem resposta?" → lista leads pendentes
    → "manda material pro João" → forward do último arquivo
    → "convida 11999..." → gera convite e manda link
    → "desconecta 11999..." → libera slot
    → Manda PDF/imagem → Cleo armazena como material

ADMINISTRAÇÃO:
  Monitor de conexão (5 em 5 min) → alerta admin se desconectar
  Subscription cron → expira assinaturas vencidas → desconecta TODAS sessões
  Cancellation cron → limpa dados após prazo
  Slots: max_connections_override permite deals customizados (10, 20, 50, 100+)
```
